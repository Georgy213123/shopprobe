# 05. Тестирование

В кейсе два объекта тестирования: демо-витрина и сам ShopProbe. Второй важнее:
инструмент, который ищет дефекты, сам должен быть проверен на ответ, известный заранее.

## Пирамида

```
                  ┌──────────────────────────┐
                  │ мета-тест ShopProbe  (2) │  чистая витрина → 0; SEEDED_BUGS=1 → все дефекты
                ┌─┴──────────────────────────┴─┐
                │ e2e витрины (10)             │  путь покупателя на 1440×900 и 390×844
              ┌─┴──────────────────────────────┴─┐
              │ ShopProbe в Chromium (20)         │  каждая проверка на своей фикстуре, CLI под tsx
            ┌─┴──────────────────────────────────┴─┐
            │ интеграционные API + PostgreSQL (20)  │  фильтры, фасеты, ошибки, режимы дефектов
          ┌─┴──────────────────────────────────────┴─┐
          │ unit: бэкенд 19, фронт 22, ShopProbe 36   │  чистая логика без сети и браузера
          └──────────────────────────────────────────┘
```

Почему так:

- **Большая часть логики — чистые функции**, и тестируется без браузера: условия фасетов,
  разбор URL каталога, редьюсер корзины, отпечаток находки, вердикт перепроверки,
  экранирование отчёта. Такие тесты идут за секунду и падают с точной причиной.
- **Проверки ShopProbe тестируются в настоящем Chromium на фикстурах**, а не на витрине.
  Фикстура — страница из десяти строк ровно с одним дефектом или ловушкой (lazy-картинка,
  поздний стиль, шум HMR). Так тест отвечает на один вопрос, и ложное срабатывание видно сразу.
- **Интеграционные — на PostgreSQL**, а не на SQLite: фасетный запрос — это `GROUP BY` и `IN`,
  их поведение должно совпадать с продом. Схема каждый раз создаётся миграциями Alembic.
- **e2e витрины немного** — по одному на историю покупателя, но на двух вьюпортах.
- **Мета-тест на вершине** проверяет весь инструмент как чёрный ящик: CLI как внешний
  процесс против живой витрины, итог — по `report.json`.

## Что проверяет каждый слой

| Слой | Где | Что проверяет |
|---|---|---|
| unit бэкенда | `backend/tests/unit` | условия SQL фильтров и фасетов (BUG-03), валидация параметров каталога, чередование нестабильного запроса, валидность SVG, совпадение `openapi.yaml` с кодом, защита тестовой базы (`_test`), порты Docker только на 127.0.0.1 |
| интеграционные | `backend/tests/integration` | `/api/catalog`: фильтры, мультивыбор, цена, наличие, сортировка, пагинация, 422; фасетные счётчики; карточка и 404; картинки; посаженные дефекты только по флагу |
| unit фронта | `frontend/src/**/*.test.ts(x)` | редьюсер корзины и хранение (мусор в localStorage, недоступное хранилище), состояние каталога в URL, формат цены, `FacetFilter`, страница корзины |
| unit ShopProbe | `probe/tests/unit` | отпечаток и шаги находки, вердикты, шкала серьёзности, нормализация консоли, фильтр шума (BUG-04), критерий битой картинки (BUG-01), конфиг, сводка, HTML-отчёт |
| ShopProbe в Chromium | `probe/tests/browser` | каждая проверка на фикстуре: находит дефект и молчит на ловушке (BUG-01, 02, 04, 05); перепроверка: 404 — подтверждено, «через раз» — нестабильно; находки ревью Codex R2, R3, R4, R7, R8 (BUG-06, BUG-07); CLI через tsx пишет отчёт и код выхода |
| e2e витрины | `e2e/tests/storefront.spec.ts` | US-01…US-04 на десктопе и мобильном; нет горизонтального скролла на четырёх страницах (BUG-05) |
| мета-тест | `e2e/tests/shopprobe-meta.spec.ts` | чистая витрина: 0 подтверждённых, код 0; `SEEDED_BUGS=1`: все шесть стабильных дефектов подтверждены, скролл только на мобильном, нестабильный запрос не подтверждён, лишних подтверждённых нет, код 1 |

## Отчёт прогона

Последний прогон: 2026-11-04, после исправлений по ревью Codex. Прогон с переменными как в CI:
`CI=1`, `DATABASE_URL=…/app`, `TEST_DATABASE_URL=…/app_test` (свой кластер PostgreSQL 16.14
на порту 55201), команда `make install lint test e2e audit` — код 0, 4 мин 19 с целиком.
macOS (Apple Silicon), Python 3.12, Node 24, Chromium из Playwright 1.62.1.

| Набор | Команда | Тестов | Результат | Время |
|---|---|---|---|---|
| бэкенд unit + integration | `make test` | 39 (19 + 20) | 39 passed | 1,9 с |
| фронт unit | `make test` | 22 | 22 passed | 1,2 с |
| ShopProbe unit | `make test` | 36 | 36 passed | 0,8 с |
| ShopProbe в Chromium | `make e2e` | 20 | 20 passed | 122,4 с |
| e2e витрины + мета-тест (чистая) | `make e2e` | 11 (10 + 1) | 11 passed | 25,8 с |
| мета-тест `SEEDED_BUGS=1` | `make e2e` | 1 | 1 passed | 1,1 мин |
| **всего** | | **129** | **129 passed** | |

Покрытие бэкенда (`pytest --cov=app`, разово на версии 1.0.0, без закрепления в CI): 96 % строк
с интеграционными тестами, 73 % — только unit. Покрытие фронта и ShopProbe не замерял:
их ключевая логика покрыта unit-тестами по функциям, а проверки — браузерными тестами,
которые coverage-инструмент Vitest без браузерного режима не видит.

Прогон ShopProbe (6 маршрутов × 2 вьюпорта, перепроверка ×3): чистая — из мета-теста, дефектная — отдельный `make probe` по стенду с `SEEDED_BUGS=1`:

| Витрина | Находок | Подтверждено | Нестабильно | Не подтвердилось | Время |
|---|---|---|---|---|---|
| чистая | 0 | 0 | 0 | 0 | ≈ 17 с |
| `SEEDED_BUGS=1` | 31 | 29 | 2 | 0 | 67,7 с |

29 подтверждённых на дефектной витрине — это шесть стабильных посаженных дефектов, умноженные
на страницы и вьюпорты, где они видны (404 стиля — на всех двенадцати визитах).
Две нестабильные — запрос `/api/recommendations` (503 через раз) и битая картинка
на главной: она стоит в блоке рекомендаций и видна только тогда, когда запрос прошёл.
Второе я не сажал отдельно, это следствие первого, и перепроверка его правильно
не подтвердила. Время укладывается в NFR-01 (меньше 3 минут). После исправления BUG-07 перепроверка гоняет
все проверки, а не только давшие находку: прогон по дефектной витрине вырос с 56 до 68 с,
браузерные тесты ShopProbe — с 54 до 122 с (в основном новые сценарии ревью с перепроверкой ×3).

`make audit`: pip-audit — уязвимостей нет; `npm audit --audit-level=high` — high и critical
нет во всех пакетах. Во фронте и ShopProbe npm сообщает 11–12 уязвимостей уровня moderate
в цепочке ESLint (minimatch) — только dev-зависимости, в сборку и рантайм не попадают.

Не проверено: `docker compose up` — Docker на машине разработки не установлен;
`docker-compose.yml` проверен только как валидный YAML.
