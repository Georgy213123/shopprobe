# ADR-0003. Перепроверка находок в чистом контексте и три вердикта

Принято 2026-10-23.

**Контекст.** Ложные находки дают нестабильная витрина и замер до того, как страница устоялась.

**Варианты.** 1) Ретраи раннера, как `retries` в Playwright Test. 2) Перепроверка каждой находки
N раз в новом контексте, вердикт по доле повторов. 3) Ручная база исключений.

**Решение.** Вариант 2. Для пары «маршрут × вьюпорт» с находками — N визитов (по умолчанию 3)
в новом `BrowserContext` без кэша и хранилища, со всеми проверками. Сравнение по отпечатку:
проверка, маршрут, вьюпорт, цель (для HTTP — метод, путь, класс ответа; для axe — правило и узлы).
N из N — подтверждено, 0 — не подтвердилось, между — нестабильно. Код выхода — только по подтверждённым.
Ретраи прячут нестабильность, здесь она остаётся в отчёте.

**Последствия.**
- Плюс: нестабильный запрос виден и сборку не валит.
- Минус: дефектная витрина проверяется вчетверо дольше чистой ([05](../../05-testing.md#прогон-shopprobe)).
- Минус: дефект реже 1 из N+1 визитов может не попасть в отчёт.
