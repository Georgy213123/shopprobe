# ADR-0004. Посаженные дефекты включаются флагом сервера, фронт узнаёт его в рантайме

- Статус: принято
- Дата: 2026-10-24

## Контекст и проблема

Мета-тест ShopProbe гоняет одну и ту же витрину в двух режимах: чистом и с дефектами.
Часть дефектов — на сервере (картинка, нестабильный запрос), часть — во фронте (консоль,
скролл, h1, контраст, 404 стиля). Нужно переключать режим, не собирая фронт дважды
и не оставляя в нём способа включить дефекты из адресной строки.

## Рассмотренные варианты

1. Переменная сборки Vite (`VITE_SEEDED_BUGS`) — две сборки фронта.
2. Параметр запроса `?bugs=1` — один стенд, режим на каждый запрос.
3. Переменная окружения бэкенда `SEEDED_BUGS`; фронт читает её из `GET /api/meta`.

## Решение

Вариант 3. Режим задаётся там, где задаются все настройки стенда, — в окружении API.
Фронт один; `useSeededBugs()` возвращает `false`, пока `/api/meta` не ответил, поэтому
в чистом режиме дефектный код не рендерится ни на мгновение. Мета-тест перезапускает
только API (`scripts/e2e.sh`), сборка фронта и `vite preview` не трогаются.

Вариант 2 отвергнут: режим «с дефектами» стал бы доступен любому посетителю по ссылке.

## Последствия

- Плюс: одна сборка, переключение за секунды; в Docker — `SEEDED_BUGS=1 make up`.
- Плюс: дефектный код помечен `data-seeded` и комментарием «Посаженный дефект» — его легко найти и не спутать с настоящим.
- Минус: фронт делает лишний запрос `/api/meta` на старте. Для демо приемлемо.
