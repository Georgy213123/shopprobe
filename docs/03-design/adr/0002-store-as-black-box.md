# ADR-0002. Витрина — чёрный ящик: интеграция только через браузер и HTTP

- Статус: принято
- Дата: 2026-10-21

## Контекст и проблема

ShopProbe должен проверять любую витрину, не только демо. Внешняя система для него —
сама витрина: чужой код, чужая сборка, иногда чужой хостинг. Вопрос — через что
с ней интегрироваться.

## Рассмотренные варианты

1. Только браузер и HTTP по `BASE_URL` и списку маршрутов в конфиге.
2. Плагин в сборку витрины (Vite/webpack), который сообщает об ошибках изнутри.
3. Чтение логов сервера витрины и её базы.

## Решение

Вариант 1. Конфиг — единственная точка связи: `baseUrl`, `routes`, `viewports`,
пороги и шаблоны игнора. Всё, что ShopProbe знает о витрине, он видит так же,
как покупатель.

Для демо-витрины это правило соблюдается тоже: ShopProbe не импортирует ни одного
модуля бэкенда или фронта, флаг `SEEDED_BUGS` не читает. Мета-тест узнаёт режим
витрины через публичный `GET /api/meta` и запускает CLI как внешний процесс.

## Последствия

- Плюс: подключение новой витрины — правка `probe.config.ts`, без изменений в её коде.
- Плюс: находки воспроизводимы любым человеком с браузером — шаги в отчёте опираются только на URL и размер окна.
- Минус: шум окружения (расширения, HMR дев-сервера) попадает в консоль; нужен фильтр по умолчанию (BUG-04).
- Минус: сценарии за авторизацией и оплатой требуют отдельного модуля сценариев — в демо не входят.
